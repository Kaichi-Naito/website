# ランキングの接続設定

元の「音ゲーランキング」を使います。コピーのスプレッドシートは作りません。

## 上位10人への変更

ゲームの表示・登録受付は上位10人です。既存のApps Scriptでも `const MAX_RANKING_ENTRIES = 20;` を `const MAX_RANKING_ENTRIES = 10;` に変更して保存し、既存のデプロイを「新バージョン」で更新してください。GitHubのCode.gsを変更するだけでは、稼働中のApps Scriptには反映されません。

未更新でもゲームは上位10人だけを表示・登録対象にしますが、サーバー側は20人のままで、同時登録時の判定に差が出る可能性があります。更新後は保存時にも10人に揃います。ランキングの登録先URLとスプレッドシートの設定は変更不要です。

## 自己ベスト更新版への切り替え（2026-09-21）

登録先URLは設定!B2に配置済みです。今回の変更には既存Apps Scriptの更新が必要です。

1. 元のスプレッドシートの **拡張機能 → Apps Script** を開きます。
2. [最新の Code.gs](https://github.com/Kaichi-Naito/website/blob/main/rhythm/ranking/Code.gs) の全文で置き換えて保存します。
3. **デプロイ → デプロイを管理 → 既存のデプロイの編集（鉛筆） → バージョン：新バージョン → デプロイ** を選びます。
4. 同じデプロイの更新ならURLは変わりません。設定!B2もそのままです。
5. ゲームを再読み込みし、1回登録後、同じブラウザでもう一度プレイしてください。高ければ同じ行が更新され、低ければ前の記録を保持します。

スコア表のP1:R1は `プレイヤーキー / 楽曲ID / 難易度` が必要です。ゲームは登録前に新方式への対応を確認します。旧プログラムのまま重複登録を増やすことはせず、更新が必要な案内を表示します。

ブラウザのlocalStorageにランダムなプレイヤーIDを保存します。公開シートには、生のIDではなく譜面ごとにSHA-256で変換したキーを記録します。IPアドレスは収集しません。別端末・別ブラウザ・シークレットモード・サイトデータ削除まで同一人物と判定するものではありません。厳密に1人1枠にする場合はログイン認証が必要です。

旧記録にはプレイヤーIDがないため、同名という理由で勝手に統合しません。新方式で登録した記録から重複防止が有効になります。譜面の内容・演奏時間を変えた場合は、従来どおり別ランキングです。

## 初回のみ必要な設定

1. スプレッドシートの **拡張機能 → Apps Script** を開きます。
2. `Code.gs` の中身を、このフォルダーの `Code.gs` の全文に置き換えて保存します。
3. **デプロイ → 新しいデプロイ → ウェブアプリ** を選択します。
4. 実行するユーザーは **自分**、アクセスできるユーザーは **全員** を選びます。
5. Googleの画面で自分のスプレッドシートへのアクセスを承認してデプロイします。
6. 発行された `/exec` で終わるウェブアプリURLを、スプレッドシートの **設定!B2** に貼り付けます。
7. ゲームの **ランキングを更新** を押します。ゲーム側のコードを書き換える必要はありません。

ソースを更新したときは「デプロイを管理」から新しいバージョンに更新します。
既存のデプロイを更新すれば、URLは維持できます。

## 楽曲一覧（譜面タブ）

1行が1曲・1難易度です。既存のA〜D列は維持し、E〜Jを追加しています。

| 列 | 項目 | 記入例 |
| --- | --- | --- |
| A | 曲名 | Rolling |
| B | 難易度 | NORMAL |
| C | 譜面 | rhythm/Rolling/Rolling_T4P_NORMAL.mid |
| D | 音源 | rhythm/Rolling/Rolling_T4P.ver.mp3 |
| E | アーティスト | PHALUX |
| F | ジャケット | images/CDjacket/Rolling500x500.png |
| G | BPM | 162（MIDIに初期テンポ指定がない場合に使用） |
| H | プレイ時間（秒） | 125.952（ゲーム側は30秒上限） |
| I | 譜面ID | rolling-normal（重複しない英数字・ハイフン・アンダーバー） |
| J | 公開 | チェックを入れると曲選択に表示 |

パスはリポジトリ内の位置です。先頭に `website/` が付いた下書きの形式も対応します。
同じ曲の別難易度を追加する場合は、新しい行に別の譜面ID・難易度・MIDIを指定します。RollingのHARDは `rhythm/Rolling/Rolling_T4P_HARD.mid` を使用します。
音源・ジャケットは同じファイルを使えます。シートの変更後はゲームページを再読み込みします。
ファイル自体を差し替えた場合はGitHub Pagesの公開完了後に再読み込みしてください。

## 保存内容と挙動

- スコアシートのA:R：曲名、プレイヤー名、スコア、精度、最大コンボ、譜面ID、判定ルール、登録日時、プレイID、PERFECT、GREAT、GOOD、MISS、判定数、空押し数、プレイヤーキー、楽曲ID、難易度。
- 読み取りはGoogle Sheetsの公開閲覧機能を使用します。登録はApps Script経由です。
- 設定!B2には公開URLだけを置きます。パスワードやAPIキーを入れる必要はありません。
- 判定ルール `beat-hold-v4`：長押しは開始時＋1拍ごとに1判定分。空押し1回につきPERFECT 1判定分を減点し、0点を下限とします。旧ルールの記録とは分けます。
- 同じ譜面の各プレイヤーの最高スコアを上位10人まで表示します。同点では先に登録した自己ベストを保持します。譜面のノート配置が変わると別ランキングになります。
- 名前は1〜16文字。入力文字列はHTMLにせず表示し、数式としても実行しません。
- 任意登録です。スキップやリトライ開始だけでは何も送信しません。
- 登録成功は、書き込み後の応答を受け取ってから表示します。
- 通信切断時は同じプレイIDで再試行するため、二重登録になりません。
- サーバー側でスコアと判定数の整合性を確認します。ただし、ブラウザーが自己申告する形式なので、本格的な改ざん防止を保証するものではありません。
- プレイヤーのGoogleログインは不要です。スプレッドシートを公開編集にはしません。

## 確認

`node --test rhythm/*.test.mjs`

実際の接続後は、30秒プレイ → 名前登録 → スコアシートに1行追加 → 別のブラウザーでもランキング表示、を確認します。
登録をスキップした場合は行が増えないことも確認します。
